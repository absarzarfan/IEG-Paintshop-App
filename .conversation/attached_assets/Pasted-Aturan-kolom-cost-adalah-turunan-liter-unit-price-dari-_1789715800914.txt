Aturan: **kolom cost adalah turunan** (`liter × unit_price` dari master harga material), jangan hardcode. Simpan `unit_price` per material + `currency` (USD) + `effective_date` agar histori cost tidak berubah retroaktif. Record lama tetap memakai harga saat transaksi dibuat.

**Master lain:** `master_sn` (mapping Serial Number ↔ Job No, contoh `359–365` untuk B180339, `212-214` untuk B190004 — dukung input range dan list), `master_operator_pic`, `master_color` (Yellow, TU Yellow, Black, TU Black, …).

### 2.2 Form Input Pengecatan (Fase 2) — mobile/tablet friendly

Header: `Job Number` (searchable dropdown) → `SN` (terfilter dari job) → `Quantity` → `Tanggal Eksekusi` → `PIC/Operator`.

Section **PRIMER** — tanggal primer, aktual `Base (l)`, `Hard (l)`, `Thinner (l)`.
Section **TOPCOAT** — tanggal topcoat (boleh beda hari dari primer, lihat sheet PAINT TRACKER: primer 03/09/2026 vs topcoat 07/09/2026), `Color` (bisa lebih dari satu warna per record, contoh baris 1: Yellow 1.1 + TU Yellow 0.225 → **dukung multi-color line per record**), aktual `Base`, `Hard`, `Thinner`.

Auto-calculation: begitu Job No + Quantity dipilih, sistem menarik target dari master:

```
target_komponen = master_job_item.<komponen> × quantity
```

Target ditampilkan read-only di sebelah kolom input aktual (layout mirror sheet: Base(l) | Target | Δ).

### 2.3 Variance Engine (Fase 3)

```
Δ = Target − Aktual
Δ dihitung TERPISAH per komponen: primer_base, primer_hrd, primer_thinner,
                                   topcoat_base, topcoat_hrd, topcoat_thinner
variance_pct = (Aktual − Target) / Target × 100   (Target > 0)
```

Status indicator:
- `Δ ≥ 0` → **HEMAT / SESUAI TARGET** → hijau
- `Δ < 0` → **BOROS / OVERCONSUMPTION** → merah/merah muda
- `Target = 0` dan `Aktual > 0` → **UNPLANNED** → abu/oranye, jangan divide-by-zero

Alert: bila `variance_pct > 10%` (threshold **configurable per Admin**, default 10) → record masuk status `Pending review`, notifikasi ke Supervisor + Admin. Supervisor `Approved` → `Completed`; `Rejected` → `Rejected` + wajib alasan, operator dapat resubmit.

Lifecycle record pemakaian (pakai pola `workflowPolicy.ts`, pure function + unit test):
`Draft → Submitted → Pending review (jika lewat threshold) → Completed | Rejected → (resubmit) → Submitted`
Resubmit **mempertahankan identity, histori, catatan, lampiran, dan `reworkCount` kumulatif**; hanya reset hasil review & keputusan terakhir.

### 2.4 Accountability (Fase 4)

- Rekap histori pemakaian per Operator/PIC: total record, total liter, jumlah overconsumption, rata-rata `variance_pct`, ranking efisiensi.
- **Audit trail wajib**: siapa, kapan (timestamp WIB), field apa, nilai lama → nilai baru, untuk setiap create/update/delete di transaksi maupun master. Append-only, tidak bisa dihapus dari UI.

### 2.5 Dashboard & Report (Fase 5)

- Rekap aktual vs target per Job No / per periode / per SN / per operator.
- Persentase efisiensi (Hemat vs Boros), tren mingguan & bulanan.
- Total cost aktual vs cost target (USD).
- **Export Excel (.xlsx) & PDF** — layout mengikuti sheet `PAINT TRACKER` (grup kolom Primer & Topcoat, kolom Target dan Δ berdampingan, conditional formatting hijau/merah ikut ter-export).
- Laporan konsumsi per Serial Number untuk keabsahan QC.
- **Summary report otomatis akhir minggu & akhir bulan** (tujuan utama sistem ini). Boundary periode memakai tanggal eksplisit + timezone bisnis `Asia/Jakarta`, bukan timezone mesin server. Response polling pakai `no-store`.
